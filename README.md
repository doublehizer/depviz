# Визуализатор графа зависимостей NuGet

Практическая работа № 2 по дисциплине «Конфигурационное управление»,
вариант 12.

## Общее описание

Консольное приложение (CLI), которое строит граф зависимостей пакета
менеджера пакетов .NET (NuGet). Готовые менеджеры пакетов и библиотеки
для получения зависимостей не используются.

Текущий этап — **этап 1 (минимальный прототип с конфигурацией)**.
Приложение читает YAML-файл настроек, проверяет все параметры и
выводит их в формате `ключ = значение`. Если в настройках есть ошибки,
выводятся **все** найденные ошибки сразу, а код выхода равен 1.

## Параметры (файл настроек)

Настройки задаются в YAML-файле. Все параметры обязательные.

| Параметр | Тип | Описание | Ошибка, если |
|---|---|---|---|
| `package` | строка | имя анализируемого пакета | пусто; есть символы кроме латинских букв, цифр, `.`, `_`, `-` |
| `repository` | строка | URL репозитория или путь к файлу тестового репозитория | пусто |
| `test_mode` | `true`/`false` | режим работы с тестовым репозиторием | не логическое значение |
| `output_image` | строка | имя файла с изображением графа | пусто; не оканчивается на `.png` |
| `ascii_tree` | `true`/`false` | выводить зависимости ASCII-деревом | не логическое значение |
| `max_depth` | целое | максимальная глубина анализа | не целое число; меньше 1 |
| `filter` | строка | подстрока для фильтрации пакетов, `""` — без фильтра | не строка |

Дополнительные проверки:

- лишний параметр — ошибка `неизвестный параметр`;
- пропущенный параметр — ошибка `параметр не задан`;
- обычный режим (`test_mode: false`): `repository` должен быть URL
  со схемой `http` или `https`;
- тестовый режим (`test_mode: true`): `repository` — путь к
  существующему файлу (считается от папки файла настроек), а имя
  пакета состоит из больших латинских букв (`A`, `B`, ...);
- файл настроек не найден, ошибка синтаксиса YAML (с номером строки),
  в файле не пары `ключ: значение` — тоже ошибки.

Пример файла настроек (`config.yaml`):

```yaml
package: Serilog.Sinks.Console
repository: https://api.nuget.org/v3/index.json
test_mode: false
output_image: graph.png
ascii_tree: true
max_depth: 3
filter: ""
```

| Параметр | Описание |

## Сборка и запуск

Нужен Python 3.9+. Единственная сторонняя библиотека — PyYAML (только
для чтения файла настроек). Сборка не требуется: при первом запуске
`run.sh` сам создаёт окружение `.venv` и ставит туда PyYAML.

Запуск:

```sh
./run.sh
./run.sh --config tests/configs/test_mode.yaml
```

Запуск автотестов:

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

Демонстрация всех видов ошибок (этап 1):

```sh
tests/stage1/demo.sh
```

| Файл настроек | Что показывает |
|---|---|
| `url_mode.yaml` | правильные настройки, обычный режим |
| `test_mode.yaml` | правильные настройки, тестовый режим |
| `all_wrong.yaml` | все 7 параметров заданы неверно |
| `missing_and_unknown.yaml` | пропущенные и лишний параметры |
| `url_mode_bad.yaml` | обычный режим, но вместо URL путь к файлу |
| `test_mode_bad.yaml` | тестовый режим: имя не из больших букв, файла нет |
| `syntax_error.yaml` | ошибка синтаксиса YAML |
| `not_mapping.yaml` | список вместо пар `ключ: значение` |
| `no_such_file.yaml` | файла настроек нет |

## Примеры использования

Правильные настройки:

```
$ ./run.sh --config tests/configs/url_mode.yaml
package = Newtonsoft.Json
repository = https://api.nuget.org/v3/index.json
test_mode = false
output_image = newtonsoft.png
ascii_tree = false
max_depth = 2
filter = Test
```

Все параметры с ошибками:

```
$ ./run.sh --config tests/configs/all_wrong.yaml
Ошибки в файле настроек tests/configs/all_wrong.yaml:
  - package: допустимы только латинские буквы, цифры, точка, _ и -
  - repository: нужна непустая строка: URL или путь к файлу
  - test_mode: нужно true или false
  - output_image: имя файла должно оканчиваться на .png
  - ascii_tree: нужно true или false
  - max_depth: должно быть не меньше 1
  - filter: нужна строка (без фильтра — пустая строка "")
```
